# Участие в разработке BottleCRM

Спасибо, что помогаете улучшать BottleCRM. Мы рады вкладу любого размера: исправлениям ошибок, новым функциям, тестам, документации и улучшениям доступности.

## Прежде чем начать

- Перед тем как открыть новую задачу, поищите среди [существующих](https://github.com/django-crm/Django-CRM/issues).
- Нашли уязвимость? Сообщите о ней закрыто, как описано в [SECURITY_RU.md](SECURITY_RU.md), а не в задаче.
- Для крупной функции или изменения архитектуры сначала откройте задачу, чтобы обсудить подход до начала реализации.
- Делайте pull request сфокусированными. Несвязанные изменения проще проверять, если они отправлены отдельно.

## Настройка окружения

Полные инструкции (клонирование, Docker, backend на `uv`, frontend на `pnpm`, запуск мобильного приложения, добавление зависимостей и запуск тестов) есть в документации, в разделе «Участие в разработке»:

- [Настройка окружения разработки](docs/RU/contributing/development-setup.md). Как запустить все три проекта локально.
- [Тестирование](docs/RU/contributing/testing.md): запуск тестов, маркеры и что проверяет CI.
- [Стиль кода](docs/RU/contributing/code-style.md): соглашения для Python, frontend и Flutter, и что CI проверяет, а что нет.
- [Структура репозитория](docs/RU/contributing/repo-layout.md): где лежит каждая часть кода.
- [Правила безопасности](docs/RU/contributing/security-rules.md). Правила, которые в этом коде не обсуждаются.
- [Добавление модели с привязкой к организации](docs/RU/contributing/adding-an-org-scoped-model.md). Что нужно новой мультитенантной модели, включая её политику RLS.
- [Локализация](docs/RU/localization/index.md). Как переводятся строки и [как добавить язык](docs/RU/localization/adding-a-language.md).

## Как отправить pull request

1. Создайте ветку от `master` с понятным названием.
2. Внесите сфокусированные изменения и, где уместно, добавьте тесты.
3. Запустите нужные проверки. См. [Тестирование](docs/RU/contributing/testing.md) и [Стиль кода](docs/RU/contributing/code-style.md).
4. Обновите документацию, если изменились поведение, настройка или публичный API.
5. Отправьте ветку и откройте pull request в `master`.

В описании pull request объясните, что изменилось, зачем и как это проверено, и приложите скриншоты, если изменился интерфейс. О том, что запускает CI и на что смотрят при ревью, см. [Pull request](docs/RU/contributing/pull-requests.md).

## Чек-лист pull request

- [ ] Изменение сфокусировано и не содержит несвязанных правок.
- [ ] Нужные проверки backend и frontend проходят.
- [ ] Новое или изменённое поведение по возможности покрыто тестами.
- [ ] Нужные миграции добавлены.
- [ ] Документация обновлена.
- [ ] В коммитах нет учётных данных, токенов и личных данных.
