# Предложения

Коммерческое предложение становится предложением, когда содержит три необязательных элемента:
вступление над позициями, предоплату, запрашиваемую при принятии, и проект, который начинается,
когда клиент принимает предложение. Клиент, как и раньше, принимает его на публичной странице
коммерческого предложения, вводя имя и email; затем сервер запускает проект, готовит черновик счёта
на предоплату, связывает оба с коммерческим предложением и уведомляет его людей. Клиенту ничего
автоматически не отправляется.

Коммерческие предложения находятся в модуле «Счета». Код находится в `backend/invoices/proposals.py`
и вызывается из `PublicEstimateAcceptView` и `PublicEstimateDeclineView` в
`backend/invoices/public_views.py`. API описан в разделе
[Счета и коммерческие предложения](../api/invoices.md#proposals).

## В коммерческом предложении {#on-the-estimate}

| Поле | Примечания |
| --- | --- |
| `introduction` | Простой текст, до 5 000 символов. Показывается над позициями на публичной странице и в PDF с сохранением переносов строк, никогда как HTML |
| `deposit_percent` | Больше 0 и не больше 100 или `null`, если предоплаты нет. Фиксируется, как только коммерческое предложение выходит из черновика, как и его позиции |
| `start_project` | Начать проект, когда клиент примет предложение. Требует компанию и модуль «Проекты» |
| `project_billing_type` | Тип выставления счетов для запускаемого проекта: `fixed_fee` (по умолчанию), `time_and_materials` или `non_billable` |

Включить `start_project` или выбрать тип выставления счетов может только администратор организации,
потому что только администратор задаёт денежные поля проекта
([Проекты](projects.md#money-is-set-by-admins)). Любому другому, кто меняет одно из них, отказывают
с сообщением «Only an admin can start a project from an estimate.» Отправка обратно сохранённого
значения изменением не считается, поэтому участник по-прежнему может править остальное в
коммерческом предложении, которое настроил администратор.

## Предоплата {#the-deposit}

Предоплата: доля итога коммерческого предложения без налога (подытог минус скидка на документ,
каждое с точностью до копейки), округлённая до копейки по правилу «половина вверх», с налоговой
ставкой коммерческого предложения, начисленной на неё так же, как начисляет налог счёт. Её
вычисляет одна вспомогательная функция, и ею пользуются публичная страница, PDF, список
коммерческих предложений и счёт на предоплату, поэтому сумма, которую видит клиент, равна сумме в
счёте. Предоплата, которая в итоге составила бы 0,00 (крошечный процент от небольшого итога или
коммерческое предложение со скидкой до нуля), не считается предоплатой: она не показывается и
черновик по ней не создаётся.

## Когда клиент принимает предложение {#when-the-client-accepts}

В той же транзакции, что и принятие, поэтому при сбое коммерческое предложение остаётся непринятым,
ничего не создаётся, и клиент может попробовать снова:

1. **Проект**, когда задано `start_project` и модуль «Проекты» включён. Он получает название по
   заголовку коммерческого предложения (или «<account>, estimate <number>», если заголовка нет),
   создаётся для компании, сделки и валюты коммерческого предложения, с `project_billing_type`,
   итогом без налога в качестве бюджета (без бюджета для неоплачиваемого проекта), активным
   статусом и сегодняшним днём как датой начала. Его люди: активные ответственные коммерческого
   предложения и его создатель. Ставки не задаются: их добавляет администратор, как требует раздел
   [Проекты](projects.md#money-is-set-by-admins).
2. **Счёт на предоплату**, если предоплата есть: черновик для компании, контакта, реквизитов
   клиента, сделки и валюты коммерческого предложения, связанный с проектом, если проект был
   запущен, с одной позицией «Deposit: <percent>% of estimate <number>, <title>». Его люди и
   команды берутся из коммерческого предложения. Он никогда не отправляется автоматически: кто-то
   проверяет его и отправляет.
3. Оба связываются с коммерческим предложением (`project`, `deposit_invoice`). Предоплата не
   является конвертацией: «Выставить счёт» остаётся доступным.
4. **Люди коммерческого предложения получают уведомление**: его создатель и активные ответственные,
   а если их нет, администраторы организации.

Принятие происходит один раз, поэтому ничего не создаётся дважды. Отклонение уведомляет тех же людей
и ничего не создаёт.

## Выставление полного счёта {#raising-the-full-invoice}

Выставление счёта по коммерческому предложению включает все позиции и переносит его проект. Если
счёт выставляется до того, как клиент принял предложение, коммерческое предложение, настроенное на
запуск проекта, запускает его в этот момент точно так же, как при принятии, без предоплаты (счёт
выставляется на всё коммерческое предложение) и без уведомления; клиент больше не может его
принять, поскольку выставление счёта помечает его принятым. Если клиент уже принял предложение, счёт
переносит проект, запущенный при принятии.
Предоплата не вычитается: позиции счёта не могут быть отрицательными, а у счетов нет кредитов,
поэтому человек убирает её, правя черновик перед отправкой. Веб- и мобильное приложения называют
счёт на предоплату перед выставлением счёта, чтобы о нём не забыли.
