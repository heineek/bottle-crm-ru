# Проекты

Проект: работа по исполнению между выигранной сделкой и счётом. К нему привязаны задачи, учтённое
время, файлы и комментарии; почасовая ставка подставляется сама при учёте времени; расход бюджета
виден в реальном времени; администратор одним действием превращает невыставленное время или долю
фиксированной суммы в черновик счёта, а ретейнер каждый месяц сам готовит свой счёт.

Проекты образуют модуль «Проекты», который по умолчанию включён во всех организациях;
администратор может выключить его в разделе [Модули](../getting-started/modules.md). Код находится в
`backend/projects/`; учёт времени и выставление счетов используют `backend/cases/time_views.py`,
`backend/cases/services/billing.py` и `InvoiceFromTimeEntriesView` в
`backend/invoices/api_views.py`.

## Запись {#the-record}

| Поле | Примечания |
| --- | --- |
| `name` | Обязательное |
| `account` | Обязательное: клиент. Должна быть компанией, которую вызывающий может открыть |
| `deal` | Необязательное: сделка, из которой вырос проект. Должна быть сделкой, которую вызывающий может открыть. Становится `null`, если сделку удалили |
| `status` | `active` (по умолчанию), `on_hold`, `completed`, `cancelled` |
| `billing_type` | `time_and_materials` (по умолчанию), `fixed_fee`, `non_billable`, `retainer` ([Ретейнеры](#retainers)) |
| `currency` | По умолчанию валюта организации |
| `budget_hours`, `budget_amount`, `hourly_rate` | Каждое необязательное, 0 или больше |
| `start_date`, `due_date` | Необязательные; срок не может быть раньше даты начала |
| `assigned_to` | Люди проекта: активные участники организации |
| `rates` | Одна ставка на человека в этом проекте, приоритетнее `hourly_rate` |
| `retainer_fee`, `retainer_hours`, `retainer_rollover`, `retainer_overage_rate`, `retainer_carried_hours` | Условия ретейнера; см. [Ретейнеры](#retainers) |
| `description`, `tags`, `custom_fields` | Как у любой записи; дополнительные поля относятся к `Project` |

### Кто что видит {#who-sees-what}

Действуют правила сделок ([Сделки](../api/opportunities.md)). Администраторы видят все проекты;
остальные видят проекты, которые создали или на которые назначены, и могут их редактировать.
Удалить проект могут администраторы и создатель; ответственный не может (`403`). Проект-ретейнер
может удалить только администратор, так как только администратор задаёт статус, завершающий его
выставление счетов. Проект, который вызывающий не может открыть, отвечает `404`, точно так же, как
несуществующий id, и так же отвечает проект другой организации. Ставки и бюджеты видны всем, кто
видит проект, а `burn.invoiced_amount` только администраторам. Выставлять счета по проекту могут
только администраторы.

### Деньги задают администраторы {#money-is-set-by-admins}

`billing_type`, `currency`, `budget_hours`, `budget_amount`, `hourly_rate`, `rates` и пять
записываемых полей ретейнера записывают только администраторы организации. У проекта-ретейнера это
относится и к `status`, поскольку он решает, за какие месяцы выставляется счёт. Для остальных эти
поля доступны только для чтения и молча игнорируются, поэтому новый проект участника получает
значения по умолчанию: время и материалы, валюта организации, без бюджетов, без ставок и без
ретейнера.
Любой, кто может создать проект, выбирает его компанию; перенести существующий проект в другую
компанию может только администратор, у остальных это игнорируется.

Валюту нельзя изменить, как только у проекта есть хотя бы одна запись времени или счёт, даже
администратору: `400` `{"currency": ["The currency cannot change once the project has time or
invoices."]}`. Отправить обратно текущую валюту можно.

### Закрытие проекта {#closing-a-project}

Установите статус `completed` или `cancelled`: это обычный способ закрыть проект, и всё остаётся на
месте. Компанию нельзя удалить, пока у неё есть проект: удаление отвечает `409` с сообщением «This
account can't be deleted while it still has projects, invoices, estimates or recurring invoices
linked to it.» Пока модуль «Проекты» выключен, отказ вместо этого называет модуль, как для любого
выключенного модуля. При удалении проекта его учтённое время, счета и задачи сохраняются, а связь с
проектом очищается, так что история выставленных счетов никогда не теряется. Запись времени,
оставшаяся в таком виде, не относится ни к обращению, ни к проекту; учёт времени, отчёт по времени
и его экспорт показывают её как не относящуюся ни к чему, и выставить по ней счёт больше нельзя.

## API {#the-api}

Все маршруты находятся под `/api/projects/`. Ошибки имеют вид `{"error": true, "errors": {...}}`, а
отсутствующий или скрытый проект отвечает `404` `{"error": true, "errors": "Project not found."}`.

| Маршрут | Что делает |
| --- | --- |
| `GET /api/projects/` | `{"projects": [...], "count": N}`, сначала новые. Фильтры: `status`, `account`, `assigned_to` (id профиля), `search` (по названию, без учёта регистра), `limit` (по умолчанию 50, не больше 200) и `offset` |
| `POST /api/projects/` | Создание; `201` `{"error": false, "id": "<uuid>", "project": <detail>}` |
| `GET /api/projects/<id>/` | Детальная карточка |
| `PATCH /api/projects/<id>/` | Любое поле создания; `rates`, если передано, заменяет весь список. Отвечает как создание, с `200` |
| `DELETE /api/projects/<id>/` | `204`; см. [Закрытие проекта](#closing-a-project) |
| `POST /api/projects/<id>/` | Добавляет комментарий (`comment`), файл (`project_attachment`) или оба, как у сделки, и отвечает детальной карточкой |
| `GET /api/projects/from-deal/<deal_id>/` | Черновик для формы нового проекта, ничего не сохраняется |
| `POST /api/projects/<id>/retainer/bill/` | Выставляет счёт за месяц ретейнера сейчас; см. [Выставить счёт за этот месяц](#bill-this-month) |

Строка списка содержит `id`, `name`, `account` (`{"id", "name"}`), `deal` (`{"id", "name"}` или
`null`), `status`, `billing_type`, `currency`, `budget_hours`, `budget_amount`, `hourly_rate`,
`start_date`, `due_date`, `assigned_to` (профили), `tags`, `burn`, `created_at` и `updated_at`, а
также поля ретейнера: пять записываемых плюс `retainer_next_month` и `retainer_last_month`.
Детальная карточка добавляет `description`, `custom_fields`, `retainer_usage`, `rates`
(`[{"profile": <profile>, "hourly_rate"}]`), `comments`, `attachments`, `invoices` (сначала новые,
только те, что вызывающий может открыть, `[]` пока модуль «Счета» выключен), `estimate` (см.
[Из принятого коммерческого предложения](#from-an-accepted-estimate)), `can_edit`, `can_delete` и
`can_bill`.

`assigned_to` и `profile` каждой ставки должны быть активными участниками организации, не больше
одной ставки на человека; всё остальное даёт `400` с указанием поля. Правка может отправить обратно
людей, которые уже есть в проекте (назначены или имеют ставку), даже если их деактивировали;
активными должны быть только добавляемые люди. Отказ называет человека и никогда не показывает id.

### Из выигранной сделки {#from-a-won-deal}

Выигранная сделка предлагает «Начать проект». `GET /api/projects/from-deal/<deal_id>/` отвечает
названием сделки, её компанией и самой сделкой (каждая в виде `{"id", "name"}`, компания `null`,
если у сделки её нет), её валютой (иначе валютой организации), id её активных ответственных, а также
`billing_type` `fixed_fee` с суммой сделки в `budget_amount`, если у сделки есть сумма, иначе
`time_and_materials` с `null`. Сделка, которую вызывающий не видит, отвечает `404`. Ничего не
создаётся, пока форма не сохранена.

### Из принятого коммерческого предложения {#from-an-accepted-estimate}

Коммерческое предложение может запросить проект при принятии клиентом
([Предложения](proposals.md)). При принятии сервер создаёт проект: с названием по заголовку
коммерческого предложения, для его компании, сделки и валюты, с `project_billing_type` коммерческого
предложения, его итогом без налога в `budget_amount` (без бюджета для `non_billable`), статусом
`active`, днём принятия (по времени организации) в `start_date`, создателем коммерческого
предложения в `created_by` и его активными ответственными и создателем в качестве людей проекта.
У проекта нет `hourly_rate` и `rates`: администратор задаёт их позже. Пока модуль «Проекты»
выключен, ничего не создаётся. Выставление счёта до того, как клиент принял предложение, запускает
проект точно так же.

Детальная карточка проекта содержит `estimate`, то есть `{"id", "estimate_number"}` коммерческого
предложения, с которого начался проект, или `null`: он также `null`, пока модуль «Счета» выключен,
и для вызывающего, который не может открыть это коммерческое предложение. Счёт, выставленный по
коммерческому предложению позже, тоже несёт ссылку на проект.

### Расход бюджета {#budget-burn}

У каждого проекта есть `burn`:

| Ключ | Значение |
| --- | --- |
| `logged_hours` | Все остановленные записи по проекту, кто бы их ни внёс |
| `billable_hours` | Оплачиваемые из них |
| `billable_value` | Оплачиваемые записи со ставкой, по собственной ставке каждой записи |
| `unbilled_value` | То же, но ещё не попавшее в счёт |
| `invoiced_amount` | Счета проекта, кроме отменённых, без налога (подытог минус скидка счёта), чтобы сравнивать с фиксированной суммой; `null` для всех, кроме администратора, и пока модуль «Счета» выключен |
| `hours_percent` | `logged_hours` к `budget_hours`, целое число; `null` без этого бюджета |
| `amount_percent` | `billable_value` к `budget_amount`, целое число; `null` без этого бюджета |

Часы и деньги передаются строками с двумя знаками после запятой. Деньги учитываются только в валюте
проекта, поэтому две валюты никогда не складываются. Запущенный таймер учитывается после остановки.

При 80% и снова при 100% от `budget_hours` или `budget_amount` каждый человек проекта и каждый
администратор организации получает одно уведомление в приложении на каждый уровень и вид, один раз
навсегда: verb `project.budget`, `data` `{"kind": "hours" | "amount", "percent": 80 | 100,
"project": "<name>"}`, ссылка `/projects/<id>`. Если расход перескакивает оба уровня сразу,
отправляется только уведомление о 100%. Проверка выполняется при учёте времени, остановке таймера
(вручную или при автоматической остановке забытого таймера), правке записи и сохранении проекта, но
не пока модуль «Проекты» выключен.

## Задачи в проекте {#tasks-on-a-project}

У задачи появляется пятый вид родителя, `project`, при чтении и записи; у задачи по-прежнему не
больше одного родителя. Список задач и доска задач принимают `?project=<id>`. См.
[Задачи](../api/tasks.md).

## Время в проекте {#time-on-a-project}

Время привязано к обращению или к проекту, но никогда к обоим.

- `GET` и `POST /api/projects/<id>/time-entries/` и `POST /api/projects/<id>/time-entries/start/`
  принимают те же тела и отвечают так же, как маршруты обращений, плюс необязательное поле `task`:
  это должна быть задача этого проекта, которую вызывающий может открыть (иначе `400`). Для учёта
  времени нужен доступ к проекту на редактирование, который у проекта совпадает с правилом чтения.
  Участник читает свои записи, администратор записи всех.
- **Ставка подставляется сама.** Запись, созданная без `hourly_rate`, получает ставку человека в
  проекте, иначе `hourly_rate` проекта, иначе никакую. Ввести ставку для времени проекта, при
  создании или правке, может только администратор; введённая участником ставка игнорируется.
  `currency` записи всегда равна валюте проекта. Время обращений сохраняет нынешнюю введённую
  ставку.
- **Оплачиваемое по умолчанию.** В проекте время оплачиваемое, если `billable` не передано как
  `false`. В проекте `non_billable` оно никогда не оплачиваемое, что бы ни было передано, при
  создании, запуске таймера и правке. Время обращений сохраняет нынешнее поведение по умолчанию (не
  оплачиваемое, если не передано).
- Запуск таймера читает `billable` как `true` или `false` (булево значение JSON или одна из этих
  двух строк); любое другое значение даёт `400` `{"billable": ["Send true or false."]}`, на
  маршрутах и обращений, и проектов.
- Один запущенный таймер на человека, на обращении или на проекте: второй запуск отвечает `409` с
  `running_entry_id`, `running_case_id` и `running_project_id` (каждое `null`, когда неприменимо).
- Остановка, правка и удаление остаются на `/api/time-entries/<id>/`. Правка может задать `task` у
  записи проекта; запись обращения не может указывать задачу.

Чтение записи времени содержит `case` (`null` для времени проекта), `project`, `project_name` и
`task`.

### Отчёты {#reports}

`GET /api/time-entries/report/` принимает `group_by=agent|ticket|project|account` и фильтры
`profile`, `account`, `project` и `billable`. Компания записи: компания её обращения или её проекта.
Время без обращения, без проекта или без компании собирается в одну именованную строку
(`No ticket`, `No project`, `No account`) с ключом `null`. Каждая строка содержит
`billable_minutes`; строки по сотрудникам также содержат `billable_share`, оплачиваемые минуты к
общему числу минут (число от 0 до 1 с двумя знаками или `null`, если времени нет): это показатель
загрузки. В экспорте CSV есть колонка `Project` после `Ticket`.

## Выставление счёта за время {#bill-the-time}

`POST /api/invoices/from-time-entries/`, только для администраторов (`403` для всех остальных,
до чтения тела). Передайте либо `account_id`, либо `project_id`:

- **`account_id` и `entry_ids`** выставляют счёт за время обращений, как и раньше: каждая запись
  должна относиться к обращению этой компании. Нужен модуль «Обращения».
- **`project_id`** выставляет счёт по проекту. Без `entry_ids` берутся все остановленные,
  оплачиваемые, ещё не выставленные записи проекта, начатые не позже `up_to` (дата, по умолчанию
  сегодня); с ними каждая запись должна относиться к проекту. Нужен модуль «Проекты».

`group_by` принимает `entry` (по умолчанию, одна позиция на запись), `person`, `task` (записи без
задачи делят одну позицию) или `single`. Количество в сгруппированной позиции: сумма часов, а цена
за единицу: общая ставка её записей; записи одной группы с разными ставками разбиваются на
отдельные позиции по ставкам.

Ответ: `201` с `invoice_id`, `invoice_number`, `currency`, `line_count`, `entry_ids` и `project_id`
(`null` при выставлении по компании). Черновик счёта несёт `project`, а его записи помечаются как
выставленные, поэтому по одной записи никогда не выставляется два счёта: явное её указание даёт
`400`, а повторный запуск по дате её пропускает. Проект или компания другой организации отвечает
`404`.

`GET /api/projects/<id>/unbilled/?up_to=<date>` (только для администраторов) показывает ту же
выборку заранее: `{"entry_count", "hours", "value", "currency", "unrated_count"}`. `unrated_count`:
сколько из этих записей не имеют ставки; они выставляются по 0.

### Счёт на сумму {#invoice-an-amount}

Для фиксированной суммы `POST /api/projects/<id>/invoice-amount/` (только для администраторов)
принимает ровно одно из двух: `amount` (больше 0) или `percent` (больше 0, не больше 100, от
`budget_amount`, который должен быть задан), а также необязательное `description` (по умолчанию
`<project name>, fixed fee`). Он создаёт черновик счёта с одной позицией для компании проекта, в
валюте проекта, со ссылкой `project`, и отвечает `201` `{"invoice_id", "invoice_number"}`. Проект
показывает администраторам общую выставленную сумму в счёт фиксированной суммы в
`burn.invoiced_amount`. Счета на процент не ограничиваются в сумме: каждый проверяется отдельно,
поэтому вместе они могут превысить фиксированную сумму.

Проект-ретейнер выставляет счета помесячно ([Ретейнеры](#retainers)); веб- и мобильное приложения
не предлагают для него «Выставить счёт за время», хотя эндпоинт не отказывает.

### Отмена освобождает время {#cancelling-frees-the-time}

Отмена счёта освобождает его записи времени, чтобы по ним снова можно было выставить счёт, если
только по нему не был записан платёж: тогда записи остаются выставленными, так как это время
оплачено. Каждый путь, который переводит счёт в «Отменён», сохраняет его через `Invoice.save()`,
который это и делает: эндпоинт отмены, админка Django и любой скрипт.

## Ретейнеры {#retainers}

Ретейнер: ежемесячная плата клиента с необязательным объёмом часов. Установите `billing_type` в
`retainer` (только администраторы) с этими полями, каждое есть в строке списка и в детальной
карточке:

| Поле | Примечания |
| --- | --- |
| `retainer_fee` | Ежемесячная плата, не меньше `0.01`. Обязательна для ретейнера: `400` `{"retainer_fee": ["Set the monthly fee."]}` |
| `retainer_hours` | Часы, входящие в плату каждый месяц, от 0 до 744 (столько часов в самом длинном месяце): выше этого `400` `{"retainer_hours": ["At most 744 hours, the hours in a month."]}`. `null` означает отсутствие объёма часов: только плата, без переработки |
| `retainer_rollover` | Переносятся ли неиспользованные часы на следующий месяц. По умолчанию `false` |
| `retainer_overage_rate` | Почасовая ставка за часы сверх объёма, 0 или больше. Обязательна для ретейнера, когда задано `retainer_hours`: `400` `{"retainer_overage_rate": ["Set the rate for hours over the allowance."]}` |
| `retainer_carried_hours` | Неиспользованные часы, переносимые в следующий счёт, 0 или больше, по умолчанию `0.00`. Записываемое, чтобы администратор мог исправить или обнулить его |
| `retainer_next_month` | Только для чтения: первый день месяца, за который выставит счёт следующий счёт ретейнера, или `null` |
| `retainer_last_month` | Только для чтения: первый день последнего месяца для выставления счёта или `null`, пока ретейнер открыт |

Проверки действуют, когда сохранённый тип выставления счетов равен `retainer`, и сверяются с
сохранёнными значениями, поэтому для перевода существующего проекта в ретейнер тоже нужна плата.
Другие типы выставления счетов хранят значения ретейнера неиспользованными. Если перевести проект
из ретейнера и обратно, плата, часы, перенос и ставка сохраняются; месяцы никогда не сдвигаются
назад, так что месяц, за который счёт уже выставлен, остаётся выставленным, а перенесённые часы
начинаются заново с 0.

### Месяцы {#months}

Месяцы считаются календарными в часовом поясе организации. Каждое создание и правка применяет три
правила:

1. **Становится ретейнером** (создан как ретейнер или переведён в него): выставление счетов
   начинается с самого позднего из текущего месяца, месяца `start_date` и месяца, который уже был
   назначен следующим, без перенесённых часов. Неактивный в этот момент проект ничего не выставляет,
   пока не станет активным.
2. **Выходит из активного состояния** (в приостановленный, завершённый или отменённый): текущий
   месяц становится последним, и счёт за него всё равно выставляется полностью.
3. **Снова активен**: сначала для каждого ещё не оплаченного месяца (от `retainer_next_month` до
   `retainer_last_month`, когда тот закончится) готовится черновик счёта от имени администратора.
   Затем выставление счетов возобновляется с текущего месяца (или более позднего, если тот уже
   назначен следующим), а месяцы между ними не выставляются. Если проект приостановлен и
   возобновлён в пределах одного месяца, черновиков не создаётся.

Пропорционального расчёта нет: неполный первый или последний месяц выставляется полностью, а
администратор при необходимости правит черновик.

### Ежемесячный счёт {#the-monthly-invoice}

Когда месяц закончился в часовом поясе организации, плановая задача готовит его счёт в течение
часа после полуночи по этому поясу. Каждый счёт: черновик для компании и в валюте проекта, связанный
с проектом, с заголовком `<project name>, retainer <Month YYYY>`, без налоговой ставки, с позициями:

- `<Month YYYY> retainer`: количество 1 по `retainer_fee`;
- `Hours over the allowance`, когда время за месяц превышает объём: сверхнормативные часы по
  `retainer_overage_rate`.

Время за месяц: все остановленные, оплачиваемые, ещё не выставленные записи проекта, начатые не
позже последнего дня месяца. Пока модуль «Учёт времени» выключен, его время не видно: тогда счёт
содержит только плату, не забирает записей и не трогает перенесённые часы, а `retainer_usage` не
показывает использованных часов. Время, внесённое с опозданием (запись от 3 ноября за 30 октября),
и время, освобождённое отменой счёта, учитываются в следующем подготовленном счёте, в объёме того
месяца; черновик за месяц, по которому счёт уже выставлен, повторно не готовится. Таймер, ещё
работающий на момент окончания месяца, учитывается после остановки, в следующем счёте. Записи
помечаются выставленными этим счётом.

Часы вычисляются из минут: три записи по 20 минут при объёме в полчаса дают 0,50 часа переработки.
Объём часов равен `retainer_hours` плюс `retainer_carried_hours`, когда перенос включён. При
включённом переносе остаток объёма (с двумя знаками) переходит на следующий месяц, без ограничения
и никогда не в виде денег; при выключенном ничего не переносится. Перенесённые часы расходуются
раньше любой переработки.

Задача готовит черновик без создателя, поэтому только администраторы видят счёт, пока его не
назначат. Каждый активный администратор организации получает уведомление в приложении на каждый
счёт: verb `project.retainer_invoice`, `data` `{"project": "<name>", "month": "YYYY-MM",
"invoice_number"}`, ссылка `/invoices/<id>`.

Месяцы, закончившиеся, пока планировщик не работал, обрабатываются по порядку при его следующем
запуске, и каждый передаёт свои неиспользованные часы следующему. Плановая задача пропускает месяц,
закончившийся, пока модуль «Проекты» или «Счета» был выключен, а не готовит его с опозданием. Она
определяет это по моменту, когда модуль последний раз был включён: месяц пропускается, если
закончился раньше, поэтому выключение и включение модуля сразу после полуночи пропускает только что
закончившийся месяц. «Выставить счёт за этот месяц», сознательное действие администратора, такого
пропуска не делает: нажатое до следующего запуска задачи, оно готовит счёт за этот месяц.
Без процесса Celery beat ничего не запускается
([Почта и Celery](../self-hosting/email-and-celery.md#running-a-worker)).

### Выставить счёт за этот месяц {#bill-this-month}

`POST /api/projects/<id>/retainer/bill/`, только для администраторов (`403` для всех остальных, до
поиска проекта). Он выставляет счёт за `retainer_next_month` сейчас: за закончившийся месяц, по
которому задача ещё не подготовила черновик, или за открытый месяц по сегодняшний день. Тело
необязательно: `{"month": "YYYY-MM"}` называет месяц, который показывал вызывающий, и отклоняется
как уже выставленный, если этот месяц больше не следующий, поэтому страница, загруженная до того,
как задача подготовила счёт за месяц, никогда по ошибке не выставит счёт за следующий. Некорректный
месяц даёт `400` `{"error": true, "errors": {"month": ["Send a month as YYYY-MM."]}}`. Счёт такой
же, как у задачи, за исключением того, что его создателем становится администратор, контактом:
самый новый контакт компании, который администратор может открыть, и никто не уведомляется. Ответ:
`201` `{"invoice_id", "invoice_number", "month": "YYYY-MM"}`; открытый месяц, выставленный таким
образом, не обрабатывается повторно по его окончании.

Отказы имеют вид `400` `{"error": true, "message": ...}`:

- «This project is not on a retainer.»
- «This retainer is not running. Make the project active to bill it.» (проект не активен и ничего
  не причитается: `retainer_next_month` позже `retainer_last_month`)
- «This retainer has ended.» (проект активен, но уже позже `retainer_last_month`)
- «This retainer starts in <Month YYYY>.» (`retainer_next_month` приходится на более поздний месяц,
  месяц `start_date`)
- «This month is already billed.» (`retainer_next_month` приходится на более поздний месяц по
  другой причине, или переданный либо прочитанный месяц тем временем выставлен задачей или другим
  нажатием)

Скрытый проект, проект другой организации или удалённый во время запроса даёт `404`.

`retainer_usage` в детальной карточке равно `null`, если проект не ретейнер, иначе показывает, что
учёл бы счёт за `retainer_next_month` сегодня:

| Ключ | Значение |
| --- | --- |
| `month` | `retainer_next_month` в виде `YYYY-MM` |
| `used_hours` | Невыставленные оплачиваемые часы, которые взял бы счёт за этот месяц, по сегодняшний день |
| `available_hours` | Объём часов плюс перенесённые часы при переносе; `null` без объёма |
| `overage_hours` | Часы сверх объёма на текущий момент, `0.00` если их нет |
| `billable_now` | Удалось бы администратору прямо сейчас «Выставить счёт за этот месяц» (с учётом того, что модуль «Счета» включён) |

## Модули {#modules}

| Маршрут | Требует |
| --- | --- |
| `/api/projects/...` | «Проекты» |
| `/api/projects/<id>/time-entries/...` | «Проекты» и «Учёт времени» |
| `/api/projects/<id>/unbilled/` | «Проекты», «Счета» и «Учёт времени» |
| `/api/projects/<id>/invoice-amount/` | «Проекты» и «Счета» |
| `/api/projects/<id>/retainer/bill/` | «Проекты» и «Счета» |
| `/api/projects/from-deal/<deal_id>/` | «Проекты» и «Воронка» |
| `/api/time-entries/...` | «Учёт времени», а также «Обращения» или «Проекты» |
| `/api/invoices/from-time-entries/` | «Счета», «Учёт времени», а также «Обращения» или «Проекты» |

«Учёт времени» больше не требует «Обращений». Пока модуль выключен, его маршруты отвечают так же,
как у любого выключенного модуля ([Модули (API)](../api/modules.md#what-an-off-module-answers)).
