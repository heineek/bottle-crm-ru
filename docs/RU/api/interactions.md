# Взаимодействия

Взаимодействие: звонок, встреча, письмо, сообщение WhatsApp или SMS, записанные на записи, либо
**запрос** (`enquiry`): обращение лида, которое записывается при каждом его поступлении через
веб-форму, вебхук лидов или адрес для лидов. Заметки остаются комментариями; взаимодействие это
отдельная запись с видом, направлением и временем, и от них отсчитывается первый ответ на лид (см.
[Ответы на лиды](../features/answering-leads.md)). Маршруты находятся в
`backend/interactions/urls.py`, представления в `interactions/views.py`, правило видимости в
`interactions/access.py`, а каждая запись проходит через `interactions/service.py`.

| Эндпоинт | Что делает |
| --- | --- |
| `GET /api/interactions/?lead={id}` | Взаимодействия записи, начиная с самых новых (или `contact=`, `account=`, `opportunity=`, `case=`) |
| `POST /api/interactions/` | Записать взаимодействие на записи (`201`) |
| `PATCH /api/interactions/{id}/` | Изменить взаимодействие |
| `DELETE /api/interactions/{id}/` | Удалить взаимодействие (`204`) |

`PUT` нет, как нет и `GET` для одного взаимодействия: список записи содержит все поля.

## Кто что видит {#who-sees-what}

У каждого взаимодействия одна **основная запись** (home): запись, на которой оно записано (для
обращения это лид или контакт, которым стал конвертированный лид). Взаимодействие видит тот, кто
может открыть основную запись, по собственному правилу этой записи (`visible_leads_qs`,
`visible_contacts_qs` и так далее), и больше никто; администраторы видят всё в своей организации,
как и для любой записи. Взаимодействие может быть связано и с другими записями, но эти связи решают
лишь, в каких ещё хронологиях оно показывается: хронология контакта показывает взаимодействие,
основная запись которого лид, только тем, кто может открыть этот лид. Вторая связь никогда не
показывает запись тому, кто не может её открыть.

Взаимодействия следуют модулю своей основной записи. Когда выключены лиды, воронка или обращения,
взаимодействие, основная запись которого лид, сделка или обращение, скрыто из всех списков и
отвечает `404`, а указание такой записи в списке или при записи взаимодействия даёт собственный
`404` модуля (см. [Ошибки: выключенные модули](errors.md#switched-off-modules)). Контакты и компании
входят в ядро.

Запись, которую вызывающий не может открыть, запись в другой организации и несуществующий id
отвечают `404` с одинаковым телом.

## Кто может его изменить {#who-may-change-one}

Изменять или удалять взаимодействие может тот, кто его записал, или администратор организации;
любой другой, кто его видит, получает `403`. Обращения и всё, что записано каналом приёма или
интеграцией (`origin`, отличный от `manual` или `phone_tap`), доступны только для чтения всем,
включая администраторов: `403`. Каждый объект содержит `can_edit` для вызывающего, чтобы клиент мог
скрыть элементы управления.

## Объект {#the-object}

```json
{
  "id": "0b8e2a8c-2d55-4f0e-9a3b-6a1d1c2f4e10",
  "kind": "call",
  "direction": "outbound",
  "occurred_at": "2026-10-24T09:14:00Z",
  "duration_seconds": 240,
  "duration_estimated": true,
  "outcome": "connected",
  "subject": "",
  "body": "Wants a viewing on Saturday.",
  "logged_by": "8a4e5b9e-...-profile-id",
  "logged_by_details": {"id": "8a4e5b9e-...", "name": "Sam", "email": "sam@example.com"},
  "participants": [],
  "lead": "5b0c5c1e-6a0e-4f43-9d6e-1f0f3c1a2b3c",
  "contact": null,
  "account": null,
  "opportunity": null,
  "case": null,
  "home": "lead",
  "origin": "phone_tap",
  "external_id": "",
  "created_at": "2026-10-24T09:19:02Z",
  "can_edit": true
}
```

- `kind`: `call`, `meeting`, `email`, `whatsapp`, `sms` или `enquiry`.
- `direction`: `inbound` или `outbound`.
- `outcome`: для звонка `connected`, `no_answer`, `voicemail`, `busy` или `wrong_number`, либо
  `""`; для любого другого вида всегда `""`.
- `logged_by`: профиль, который записал взаимодействие, или `null` для запроса (`enquiry`) или строки,
  записанной интеграцией.
- `participants`: список `{name, email, phone}`, который записывают интеграции; от клиента не
  принимается.
- `home`: `lead`, `contact`, `account`, `opportunity` (сделка) или `case` (обращение); одноимённое
  поле содержит её id.
- `origin`: `manual` или `phone_tap` для записи, сделанной человеком; `intake`, `email` или
  `webform` для запроса, по пути, которым оно поступило; в остальных случаях собственный ключ
  интеграции.

## Список взаимодействий записи {#listing-a-records-interactions}

`GET /api/interactions/?lead={id}` принимает ровно один из параметров `lead`, `contact`, `account`,
`opportunity` и `case`; ни одного, два или некорректный id дают `400`. Ответ имеет вид
`{"interactions": [...], "count": n}`, начиная с самого нового `occurred_at`, и содержит только
взаимодействия, основную запись которых вызывающий может видеть. `count` это их общее число; `limit`
(по умолчанию 50, не больше 200) и `offset` листают их, а значение, не являющееся неотрицательным
числом, заменяется значением по умолчанию.

## Запись взаимодействия {#logging-one}

`POST /api/interactions/` с полями:

| Поле | |
| --- | --- |
| `kind` | Обязательно. Не `enquiry`: запросы записываются при поступлении лида |
| `direction` | `outbound` (по умолчанию) или `inbound` |
| `occurred_at` | По умолчанию текущий момент. Больше чем на пять минут в будущем отклоняется |
| `duration_seconds` | Целое число секунд или `null` |
| `duration_estimated` | `true`, если время приблизительное (мобильное приложение оценивает звонок по времени отсутствия) |
| `outcome` | Только для звонков; для любого другого вида даёт `400` |
| `subject` | До 200 символов |
| `body` | До 10 000 символов |
| `origin` | `manual` (по умолчанию) или `phone_tap` |
| `lead`, `contact`, `account`, `opportunity`, `case` | Ровно одно, оно становится основной записью |

`logged_by`, `org`, `home`, `participants` и `external_id` устанавливает сервер; если тело их
указывает, они не читаются. Запись должна быть такой, которую вызывающий может открыть (иначе
`404`). Для обращения (`case`) вызывающий также должен иметь право работать с ним: наблюдатель,
который может читать обращение, но не отвечать в нём, получает `403`. Ответ `201` с объектом.

Ошибки имеют обычную форму (см. [Ошибки](errors.md#validation-errors)):

```json
{"error": true, "errors": {"outcome": ["Only a call has an outcome."]}}
```

## Изменение взаимодействия {#changing-one}

`PATCH /api/interactions/{id}/` принимает поля, перечисленные выше. Вид, основная запись и связи с
записями никогда не меняются: передать их обратно без изменений можно, а другое значение даёт `400`.
Действуют те же правила, что при записи (у встречи нет итога, не больше чем на пять минут вперёд).

`DELETE /api/interactions/{id}/` отвечает `204`.

## Поля ответа лида {#a-leads-response-fields}

Каждая запись, затрагивающая лид (запись, изменение или удаление связанного с ним взаимодействия),
пересчитывает `first_response_at`, `first_response_by` и `last_outbound_at` лида по его сохранённым
взаимодействиям, поэтому удалённый звонок или звонок с более ранним временем учитываются сразу, а
лид, единственный ответ которому удалён, снова ждёт ответа. Удаление записи, которая является
основной для взаимодействия (звонки конвертированного лида хранятся на его контакте), удаляет и
взаимодействие, а каждый связанный с ним лид пересчитывается после фиксации удаления. Учитывается
каждый **исходящий** звонок, встреча, письмо, сообщение WhatsApp или SMS, каким бы ни был его
`origin` и независимо от наличия `logged_by`: сообщение интеграции отвечает лиду, как и звонок
участника, которого потом удалили из организации (его `logged_by` становится `null`). Звонок без
ответа тоже учитывается. Входящие сообщения и запросы не учитываются никогда.

- `first_response_at` это самое раннее из них; `first_response_by` это человек, который его
  записал, или `null`, если никто.
- `last_outbound_at` это самое позднее.
- Ни одно из них никогда не раньше `created_at` лида: звонок, записанный со временем раньше
  внесения лида, даёт время ответа ноль, и лид не считается ожидающим.
- Дата `last_contacted` лида переносится на дату `last_outbound_at` по времени организации, когда
  она позже сохранённой даты; назад она никогда не сдвигается.

Эти поля записываются прямо в строку лида, поэтому не отправляют вебхук `lead.updated` и не
запускают правила автоматизации; слушать нужно событие `interaction.created`. Поля, список лидов без
ответа и время ответа описаны в разделе [Лиды](leads.md).

## Обращения, конвертация и слияния {#enquiries-conversion-and-merges}

Каждое поступление через веб-форму, вебхук лидов или адрес для лидов является `enquiry` (входящее,
без `logged_by`, `subject` называет форму, вебхук или адрес, `body` содержит сообщение) на лиде,
который оно создало или с которым объединилось. Повторное обращение от конвертированного лида
попадает на контакт, которым он стал, и связывается с компанией этого контакта и с лидом. Повторная
отправка от отправителя, получившая ответ `duplicate`, ничего не записывает. См.
[Сбор лидов](../features/lead-capture.md).

Конвертация лида сохраняет связь каждого взаимодействия с лидом, переносит его основную запись на
новый контакт (на компанию, если конвертация не создала и не связала контакт) и связывает компанию
и сделку. Слияние одного лида с другим переносит взаимодействия поглощаемого лида на сохраняемый и
пересчитывает его поля ответа. Удаление записи удаляет взаимодействия, для которых она основная,
пересчитывая все лиды, с которыми они были связаны, а с остальных только снимает связь.

## Вебхуки и токены {#webhooks-and-tokens}

`interaction.created` отправляется для каждого взаимодействия, записанного вручную или каналом
приёма (см. [Вебхуки](../integrations/webhooks.md#events)).

Для персональных токенов доступа ресурс называется `interactions`: `interactions:read` для списка,
`interactions:write` для записи, изменения и удаления (см.
[Токены и API-ключи](tokens-and-api-keys.md#scopes)). Токену нужна также область ресурса основной
записи, та же, что нужна комментариям этой записи: `leads`, `contacts`, `accounts`, `opportunities`
или `cases`, `read` для списка и `write` для записи, изменения или удаления. Без неё ответом будет
тот же `403`, который даёт middleware, с указанием недостающей области:

```json
{"detail": "This token is not scoped for read access to leads. It needs the leads:read scope."}
```

Хронология не показывает взаимодействия, основная запись которых относится к ресурсу, недоступному
токену на чтение, поэтому токен только с `contacts:read` не видит звонки контакта, основная запись
которых лид. API-ключ организации читает любую хронологию и ничего не записывает. Сеанс, в который
выполнен вход, областями не ограничен.
