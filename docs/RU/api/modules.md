# Модули

Администратор организации может отключить для неё целые разделы BottleCRM. На этой странице описана
сторона API: как прочитать и изменить настройку, что отвечает отключённый модуль и что продолжает
работать или останавливается, пока он отключён. Та же функция с точки зрения администратора описана
в разделе [Модули](../getting-started/modules.md).

Каталог модулей находится в `backend/common/modules.py`; эндпоинты: `OrgModulesView`
(`backend/common/views/module_views.py`) и `change_modules`
(`backend/common/module_settings.py`).

Отключение модуля никогда не удаляет и не меняет записи. Всё по-прежнему хранится и возвращается,
когда модуль снова включают.

## Модули {#the-modules}

| Ключ | Название | Что охватывает | Требует |
| --- | --- | --- | --- |
| `deals` | Воронка | Сделки, воронки сделок, позиции, доска сделок и время на этапах. | |
| `leads` | Лиды | Лиды, воронки лидов, импорт и экспорт лидов. | |
| `goals` | Цели | Цели продаж, рейтинг и история целей. | `deals` |
| `tasks` | Задачи | Задачи, доски, календарь задач и его календарная лента. | |
| `tickets` | Обращения | Обращения, согласования, аналитика обращений, маршрутизация, эскалация, политика повторного открытия, рабочие часы, сохранённые ответы, входящая почта, CSAT и обращения из портала. | |
| `knowledge_base` | База знаний | Статьи, публичный справочный центр и статьи в портале. | |
| `documents` | Документы | Документы и их скачивание. | |
| `projects` | Проекты | Проекты, их участники, ставки и бюджеты, задачи и время по ним, а также выставление счетов за время проекта. | |
| `invoices` | Счета | Счета, коммерческие предложения, регулярные счета, шаблоны счетов, отчёты по счетам, выписки по компаниям, а также публичные ссылки на счета и коммерческие предложения. | |
| `timesheet` | Учёт времени | Записи времени, учёт времени и отчёт по времени. | |

Группы в порядке выдачи: `sell` (сделки, лиды, цели), `serve` (задачи, обращения, база знаний,
документы, проекты) и `bill` (счета, учёт времени). Внутри группы модули идут в сохранённом порядке
организации.

Название следует терминологии организации: организация, которая называет сделки «Opportunities»,
видит это название для `deals`, и так же для `leads` и `invoices`. Все сообщения о модулях
используют название организации.

**Требования.** Модуль, которому нужен другой, доступен только пока доступен тот. Целям нужна
Воронка. Отключение нужного модуля делает зависимый недоступным, не
меняя его собственной настройки, поэтому при повторном включении нужного модуля зависимый
восстанавливается.

## Чтение настройки {#read-the-setting}

`GET /api/org/modules/`, доступно любому участнику организации.

```json
{
  "modules": [
    {
      "key": "deals",
      "label": "Pipeline",
      "group": "sell",
      "covers": "Deals, deal pipelines, line items, the deal board and stage aging.",
      "stops": "Everything in Pipeline leaves every menu, search and Today, and stale-deal emails stop. Converting a lead no longer creates a deal, and Goals switches off too.",
      "enabled": false,
      "available": false,
      "needs": null
    },
    {
      "key": "goals",
      "label": "Goals",
      "group": "sell",
      "covers": "Sales goals, the leaderboard and goal history.",
      "stops": "Goals leave every menu, and goal milestone emails stop.",
      "enabled": true,
      "available": false,
      "needs": "deals"
    }
  ],
  "can_edit": true
}
```

В ответе все десять строк (здесь показаны две). `enabled` это собственная настройка модуля;
`available` равно `enabled`, если требуемый модуль доступен. `stops` это текст подтверждения,
который администратор читает перед отключением модуля, уже с названием из терминологии организации.
`can_edit` равно true для администраторов и false для участников.

Запрос без сессии отвечает `403` (как и любой неаутентифицированный запрос к API), как и сессия без
организации.

## Изменение настройки {#change-the-setting}

`PUT /api/org/modules/`, только для администраторов. Оба поля обязательны, и тело полностью
заменяет настройку:

```json
{"off": ["tickets", "timesheet"], "order": ["deals", "leads", "goals", "tasks", "tickets", "knowledge_base", "documents", "projects", "invoices", "timesheet"]}
```

`off` перечисляет модули, которые нужно отключить; все не названные модули включены. `order`
перечисляет ключи модулей в нужном организации порядке; модули упорядочиваются только внутри своей
группы, а модуль, не указанный в `order`, идёт после названных. Успешный `PUT` отвечает `200` с тем
же телом, что и `GET`. `PATCH` возвращает `405`.

Участнику отказывают с `403`:

```json
{"error": true, "errors": "Only admins can switch modules on or off."}
```

Тело проверяется до любого сохранения, и некорректный запрос ничего не меняет. Ответ `400` содержит
проблемы в `off` и `order`:

| Проблема | Поле | Сообщение |
| --- | --- | --- |
| Поле отсутствует | `off` или `order` | `This field is required.` |
| Не список строк | `off` или `order` | `Send a list of module keys.` |
| Ключ, который не является модулем | `off` или `order` | `Unknown module: "crm".` (по одной записи на ключ) |
| Ключ указан дважды | `order` | `Name each module once.` |
| Модуль включается, а требуемый им остаётся отключённым | `off` | `Goals needs Pipeline. Switch Pipeline on first.` |
| Веб-форма всё ещё принимает заявки | `off` | `Leads still receives submissions from the published web form "Contact us". Unpublish it first, so no submission is lost.` |
| Несколько таких форм | `off` | `Tickets still receives submissions from 2 published web forms: "Billing help", "Zed help". Unpublish them first, so no submission is lost.` |
| Активный почтовый ящик | `off` | `Tickets still receives email at help@example.com. Switch that mailbox off first, so no email is lost.` |
| Несколько активных почтовых ящиков | `off` | `Tickets still receives email at 2 mailboxes: a@example.com, b@example.com. Switch them off first, so no email is lost.` |

`off` может содержать сразу несколько сообщений. Списки форм или почтовых ящиков называют не больше
пяти, а дальше пишут `and N more`. Проверки форм и почтовых ящиков применяются только к модулю,
который изменение делает недоступным, поэтому администратор может менять порядок, пока модуль уже
отключён. Формы для лидов и активные адреса для лидов относятся к Лидам, а формы для обращений и активные
почтовые ящики обращений к Обращениям.

Тело, которое не является корректным JSON, получает собственный ответ DRF `400`,
`{"detail": "JSON parse error ..."}`.

Изменение, которое меняет список отключённых модулей или порядок, записывается в
[журнал аудита безопасности](audit-log.md) как `MODULES_CHANGED`.

## Что отвечает отключённый модуль {#what-an-off-module-answers}

Запрос авторизованного пользователя к маршруту недоступного модуля отвечает `404` на любой метод
(`GET`, `HEAD`, `OPTIONS`, `POST`, `PUT`, `PATCH`, `DELETE`):

```json
{"detail": "Tickets is switched off for this organization.", "code": "module_off", "module": "tickets"}
```

Это относится одинаково к сессии, персональному токену доступа и API-ключу организации. Называется
тот модуль, который действительно отключён: при включённых Целях и отключённой Воронке маршрут целей
называет `deals`. Собственный отказ персонального токена доступа по области действия (`403`)
по-прежнему проверяется первым, а API-ключ организации работает только на чтение, поэтому запись с
ним отклоняется, как и всегда.

Маршруты входящих почтовых ящиков (`/api/cases/mailboxes/`) относятся к Обращениям или Лидам и
доступны, пока включён любой из них, поскольку почтовый ящик создаёт обращения или лиды. Некоторым
маршрутам нужен больше чем один модуль. Времени по обращению нужны Обращения и Учёт времени,
времени по проекту нужны Проекты и Учёт времени, а маршрутам под `/api/time-entries/` нужен Учёт
времени и либо Обращения, либо Проекты. Созданию счёта из сделки нужны Счета и Воронка. Созданию
счёта из записей времени нужны Счета, Учёт времени и либо Обращения, либо Проекты, а затем Обращения,
чтобы выставить счёт за время по обращениям компании, или Проекты, чтобы выставить счёт по проекту.
Предпросмотру невыставленного времени проекта нужны Проекты, Счета и Учёт времени, выставлению счёта
на сумму нужны Проекты и Счета, а черновику проекта из сделки нужны Проекты и Воронка. Товары относятся к Воронке или Счетам и доступны, пока включён любой
из них. `GET /api/org/help-center/` это маршрут настроек Базы знаний, и пока она отключена, он
отвечает тем же `404` на любой метод.

Всё, что не входит в десять модулей (компании, контакты, веб-формы, вебхуки, автоматизация, поиск,
дашборд и остальная часть `/api/org/`), доступно всегда. `/api/interactions/` тоже относится к ядру,
но запрос, который называет лид, сделку или обращение, отвечает `404` этого модуля, пока он
отключён, а взаимодействия, привязанные к такой записи, не попадают ни в один список (см.
[Взаимодействия](interactions.md#who-sees-what)).

### Публичные, портальные и входящие точки входа {#public-portal-and-inbound-entry-points}

Это не запросы авторизованных пользователей, поэтому они отвечают так же, как для несуществующей
ссылки, и никогда не называют модуль. Единственное исключение: вебхук лидов. Запрос, содержащий
его ключ, уже доказывает, что отправитель принадлежит самой организации, поэтому ему сообщают,
почему ничего не создано.

| Точка входа | Модуль | Ответ, пока модуль отключён |
| --- | --- | --- |
| Публичные ссылки на счёт и коммерческое предложение (просмотр, PDF, принятие, отклонение) | Счета | `404` `{"error": true, "message": "Invoice not found or link expired"}` (то же тело для ссылки на коммерческое предложение) |
| Ссылка на опрос CSAT | Обращения | `410` `{"error": "Survey link is no longer valid."}` |
| Вебхук входящей почты для почтового ящика | Обращения, или Лиды для адреса лидов | `404` `{"error": true, "errors": "Mailbox not found"}` |
| Общий приёмник сгенерированных адресов | Обращения или Лиды, по почтовому ящику каждого получателя | `200`, а почта этого получателя отбрасывается |
| Обращения в портале (список, создание, просмотр, комментарий) | Обращения | `404` `{"error": "Case not found"}` |
| Статьи в портале (список, просмотр) | База знаний | `404` `{"error": "Article not found"}` |
| Подсказки статей в портале | База знаний | `200` `{"articles": []}`, как при пустом запросе |
| Публичный справочный центр | База знаний | `404` `{"error": "Not found"}` |
| Ссылка на календарную ленту | Задачи | `404` `{"error": "Not found"}` |
| Страница, описание и отправка веб-формы | Лиды или Обращения, по цели формы | `404`, как для неизвестной формы |
| Вебхук лидов (`POST /api/public/leads/<intake_id>/`) | Лиды | `403` `{"detail": "Leads are switched off for this organization."}` на запрос с ключом вебхука, записывается как отклонённая доставка; без ключа `401`, как для любого неверного ключа |

CORS-заголовки ответа веб-формы следуют тому же правилу: пока целевой модуль формы отключён, они
совпадают с заголовками неизвестной формы, так что посторонний не может понять, какой это случай.
Вход в портал не затрагивается.

## Веб-формы {#web-forms}

Форма относится к Лидам или Обращениям по своему `target`. Пока этот модуль отключён:

- Публикация формы отклоняется с `400`: `Leads is switched off for this organization. Switch
  it on before publishing this form.`
- Создание формы без `target` при отключённых Лидах даёт `400` в поле `target`, потому что цель по
  умолчанию `lead`. Выбор цели, модуль которой отключён, или смена цели формы на такую отклоняется
  так же, с сообщением о модуле.
- Уже опубликованную форму нельзя оставить без модуля: отключение модуля отклоняется, пока она
  опубликована (см. таблицу выше).

## Записи, ссылающиеся на отключённый модуль {#records-that-mention-an-off-module}

Ответы сохраняют свои ключи, когда встраивают записи отключённого модуля; встроенная часть при этом
пустая: списки равны `[]`, счётчики `0`, а одиночные ссылки и сводки `null`. Отдельные случаи:

- Запись времени сохраняет доступное только для чтения булево поле `invoiced`, пока Счета отключены;
  её `invoice` равно `null`.
- `project` задачи равно `null`, пока отключены Проекты, а `deal` проекта равно `null`, пока
  отключена Воронка. Список `invoices` проекта равен `[]`, пока отключены Счета.
- `next_activity` сделки равно `null`, пока отключены Задачи.
- `used_on` товара равно `0`, пока отключены Счета.
- Payload вебхуков задач по-прежнему содержит голые id сделки, обращения или лида задачи.

Запись, в которой ссылка на запись отключённого модуля опущена или передана как `null`, сохраняет
уже сохранённую ссылку. Запись, называющая другую запись отключённого модуля, даёт `400` в этом поле
с сообщением о модуле. Выбор события вебхука, списка сохранённого представления, цели
дополнительного поля или цели веб-формы из отключённого модуля отклоняется так же.

Модулям следуют и другие части системы:

- **Сохранённые представления** отключённого модуля не попадают в список и отвечают `404`; создать
  такое представление нельзя.
- **Вебхуки.** Для отключённого модуля ничего не отправляется, и каталог событий его не содержит.
  Эндпоинт сохраняет уже записанные события отключённого модуля, а подписка на новое даёт `400` в
  `events` с сообщением о модуле. Уже поставленные в очередь доставки всё равно отправляются.
- **Автоматизация.** Правило, объект которого относится к отключённому модулю, показывается в списке
  со статусом `paused` и текстом `Paused: Tickets is switched off` и не выполняется. Его всё ещё можно
  включить. Создание правила на таком объекте или изменение объекта, триггера, условий, действий или
  режима совпадения правила даёт `400` с сообщением о модуле. Пока отключены Задачи, `actions`
  каталога не содержит `create_task`, а шаг «Создать задачу», которого ещё нет в сохранённом
  правиле, даёт `400` в `actions[N].type` с сообщением о модуле. Шаг, который в правиле уже есть,
  сохраняется и пропускается при выполнении правила.
- **Теги** не учитывают использование в отключённом модуле в помодульных показателях и в
  `usage_labels`, а тег,
  используемый только отключённым модулем, никогда не считается неиспользуемым.
- **Пакеты и демонстрационные данные.** Применение пакета сообщает, что части отключённого модуля
  пропущены, с сообщением о модуле. Очистка демонстрационных данных сохраняет демонстрационные строки
  отключённого модуля и сообщает о них в `switched_off_by_type`.

## Задания по расписанию {#scheduled-jobs}

Задания по расписанию из этой таблицы пропускают организацию, у которой модуль отключён, а снова
включённый модуль начинает с чистого листа: задания не обрабатывают даты, прошедшие, пока он был
отключён.

| Задание | Пока модуль отключён | После включения |
| --- | --- | --- |
| Регулярные счета | Ничего не создаётся и не отправляется. | Каждое расписание переходит на следующую дату после сегодняшней. Пропущенное не выставляется. |
| Просроченные счета и истёкшие коммерческие предложения | Не помечаются. | Счета с прошедшим сроком оплаты становятся Просроченными, а коммерческие предложения с прошедшим сроком действия Истёкшими, молча: без вебхука, правила или письма. |
| Напоминания об оплате | Не отправляются. | Напоминание, день которого пришёлся на время отключения, позже не отправляется; следующее по графику отправляется в свой день. |
| Оповещения о застрявших сделках (Воронка) | Не отправляются. | По сделке, которая уже застряла к моменту включения, оповещения не будет. |
| Письма о вехах целей (Цели) | Не отправляются. | Уже достигнутые вехи считаются объявленными, поэтому отправляются только новые. |
| Эскалация по SLA (Обращения) | Проверка пропускает организацию. | Срок, прошедший во время отключения, никогда не эскалируется. |
| Зависшие таймеры (Учёт времени) | Запущенный таймер не останавливается. | Таймеры, зависшие во время отключения, остаются запущенными, пока их не остановит владелец. |
| Счета по ретейнерам (Проекты и Счета) | Пока любой из них отключён, черновики счетов по ретейнерам не создаются. | Задание по расписанию пропускает месяц, закончившийся до последнего включения модуля, а не выставляет его с опозданием; следующие месяцы выставляются как обычно. Кнопка администратора **Выставить счёт за месяц** такого пропуска не делает, поэтому, нажатая до следующего запуска задания, она создаёт черновик за этот месяц. |

Задания очистки модули не проверяют. Они удаляют прочитанные уведомления, запуски автоматизации и
журналы доставки вебхуков старше срока хранения, а также истёкшие токены входа, независимо от того,
что организация отключила. Уже поставленные в очередь доставки вебхуков всё равно отправляются.

Уже поставленные в очередь письма клиентам (опрос, уведомление портала, счёт, коммерческое
предложение, напоминание об оплате) отбрасываются, если к моменту отправки их модуль отключён.
Отправка черновика счёта или коммерческого предложения помечает его Отправленным до постановки письма
в очередь, поэтому документ, письмо которого было так отброшено, остаётся помеченным как
Отправленный; отправьте его снова, когда Счета будут включены.

## Удаление при отключённом модуле {#deleting-around-an-off-module}

Пока модуль отключён, его записи скрыты, поэтому удаление, которое уничтожило бы их или было бы ими
заблокировано, вместо этого отклоняется. Удаление компании, обращения или человека отвечает `409`:

```json
{"error": true, "errors": "This account has 3 tickets. Tickets is switched off, so switch it on to review them before deleting.", "code": "module_off", "module": "tickets"}
```

Сообщение имеет вид `<Subject> has N <things>. <Label> is switched off, so switch it on to review
them before deleting.` (`it ... it` для одной записи). Проверка прав выполняется первой, поэтому
участник, которому нельзя удалить запись, всё равно получает `403`. Что может заблокировать
удаление:

| Что удаляется | Что затрагивает |
| --- | --- |
| Компания | Её обращения, сделки, счета, коммерческие предложения, регулярные счета и проекты |
| Обращение | Его записи времени |
| Человек (профиль пользователя в организации) | Его записи времени, согласования, отслеживаемые обращения, сохранённые ответы, доски, участие в досках и ставки в проектах |

Отвязка не меняется: удаление контакта из обращения или сделки из счёта работает как всегда. Сайт
администрирования Django предназначен для операторов и модулями не ограничивается; удаление
пользователя там удаляет его профили и их записи.
