# Сохранённые представления

Сохранённое представление состоит из названия и набора фильтров списка и хранится для одного человека,
чтобы он мог одним нажатием вернуть отфильтрованный список. Его поддерживают те же шесть встроенных списков,
что [экспортируются в CSV](exports.md): лиды, контакты, компании, сделки, обращения и счета. Маршруты
находятся в `backend/common/urls.py`, представления в `common/views/saved_view_views.py`, а правила того,
что может хранить представление, в `common/saved_views.py`.

Какие списки поддерживают представления, определяет реестр объектов (`common/object_registry.py`):
запись, у которой `list_spec` называет `SavedList`, поддерживает представления, а `saved_lists(org)`
собирает списки, которые есть у организации. Установленное приложение, которое добавляет записи в
реестр через `register_hook`, так же добавляет и свои списки.

| Эндпоинт | Что делает |
| --- | --- |
| `GET /api/saved-views/` | Собственные представления вызывающего; `?module=<list>` для одного списка |
| `POST /api/saved-views/` | Сохраняет представление |
| `GET /api/saved-views/{id}/` | Одно из представлений вызывающего |
| `PATCH /api/saved-views/{id}/` | Переименовывает его или заменяет фильтры |
| `DELETE /api/saved-views/{id}/` | Удаляет его (`204`) |

`PUT` не поддерживается: у представления можно изменить две вещи, и `PATCH` меняет любую из них.

## Видно только тому, кто сохранил {#private-to-the-person-who-saved-it}

Каждый поиск фильтрует по организации вызывающего и по его собственному профилю, в том числе для
администраторов: администратор не может просматривать или открывать представления участника. Чужой id
на любом методе даёт `404` с тем же телом, что и несуществующий id, поэтому id нельзя прощупать (см.
[Ошибки: «Не найдено» или «запрещено»](errors.md#not-found-versus-forbidden)). Таблица также находится
под row-level security по организации.

`org` и `profile` устанавливает сервер. Тело, в котором указано любое из них, отклоняется с `400`, а не
просто теряет этот ключ:

```json
{"profile": ["This is set by the server."]}
```

Для персональных токенов доступа ресурс называется `saved-views`: `saved-views:read` для просмотра
списка и открытия, `saved-views:write` для сохранения, переименования и удаления (см.
[Токены и API-ключи](tokens-and-api-keys.md#scopes)).

## Объект {#the-object}

```json
{
  "id": "5b0c5c1e-6a0e-4f43-9d6e-1f0f3c1a2b3c",
  "module": "cases",
  "name": "Urgent, mine",
  "filters": {
    "status": ["New", "Assigned", "Pending"],
    "priority": ["Urgent"],
    "assigned_to": ["8a4e...-profile-id"]
  },
  "created_at": "2026-09-26T10:04:11.201Z",
  "updated_at": "2026-09-26T10:04:11.201Z"
}
```

`module` содержит имя списка, строку не длиннее 40 символов: `leads`, `contacts`, `accounts`,
`opportunities` (сделки), `cases` (обращения), `invoices` или имя списка, который добавляет
установленное приложение. После создания представления оно не меняется; `PATCH` с другим списком даёт
`400`.

Сохранение представления для списка, которого у организации нет, даёт `400` в `module`: сообщение о
модуле, если отключён модуль встроенного списка, а иначе такое:

```json
{"module": ["\"tasks\" is not a valid choice."]}
```

`GET /api/saved-views/?module=<name>` для неизвестного имени отвечает `400` с перечнем списков,
которые есть у организации, а для встроенного списка, модуль которого отключён, возвращает пустой
список.

Представление, списка которого у организации больше нет (его модуль отключён или список приложения
исчез), не попадает в список и отвечает `404`, но продолжает храниться: оно вернётся вместе со
списком.

`filters` хранит собственные параметры запроса списка, каждый в виде списка значений, поэтому
представление применяется отправкой их в список как есть: пример выше соответствует
`GET /api/cases/?status=New&status=Assigned&status=Pending&priority=Urgent&assigned_to=...`, а та же
строка запроса к `GET /api/cases/export/` выгружает его. Значение, отправленное одной строкой,
сохраняется как список из одного элемента, а пустые значения отбрасываются.

Ответ со списком содержит лимит рядом с представлениями:

```json
{"saved_views": [ { "...": "the object above" } ], "limit": 25}
```

## Что может хранить представление {#what-a-view-may-hold}

Представление проверяется до сохранения, поэтому неправильное представление сразу получает `400`, а не
превращается в список, который ломается при каждом применении:

- **Только параметры, которые читает его список.** Допустимый набор каждого списка выписан в его
  `SavedList` (`common/saved_views.py`) рядом с функцией, которой список строит свой queryset, а тест
  читает встроенные функции и доказывает, что они согласованы. Фильтр по дополнительному полю
  `cf_<key>` принимается в каждом списке и проверяется по типу своего поля (см.
  [Соглашения](conventions.md#filtering-and-search)). Пагинация (`limit`, `offset`) и всё остальное отклоняется:
  `{"filters": ["This list does not filter by: limit."]}`.
- **Значения, которые список умеет разобрать.** Фильтры проходят через собственный разбор параметров
  списка (queryset строится, но не вычисляется), поэтому некорректный id, дата или число отклоняются
  с сообщением самого списка: `{"filters": ["assigned_to: 'x' is not a valid id."]}`, или
  `{"filters": ["cf_bedrooms: must be a number"]}` для числового поля. Значение, которое
  разбирается, но ничему не соответствует (например, несуществующий статус), сохраняется ровно так, как
  его принял бы список.
- **Ограничения.** Не более 30 параметров, 50 значений на параметр и 200 символов на значение. Каждое
  значение должно быть текстом.

Id, которые хранит представление, являются значениями фильтров, а не ссылками, которые разрешает
сервер: при применении представления они отправляются обратно в список, который применяет собственное
правило чтения, поэтому представление не может показать кому-либо запись, которую не показал бы список.

## Названия и лимит {#names-and-the-cap}

Название обязательно, обрезается по краям и содержит не более 100 символов. Названия уникальны для
пары «человек и список» без учёта регистра, поэтому `Hot leads` и `hot leads` нельзя сохранить оба для
лидов; совпадение даёт `400`, в том числе когда два сохранения одновременно проходят проверку:

```json
{"name": ["You already have a view with this name for this list."]}
```

То же название можно использовать в другом списке или другому человеку.

Один человек может хранить не более 25 представлений на список (`MAX_VIEWS_PER_LIST`). Сохранение ещё
одного даёт `400`; переименование и изменение фильтров существующего представления при достигнутом
лимите по-прежнему работают:

```json
{"non_field_errors": ["You can save at most 25 views for one list."]}
```

## В приложениях {#in-the-apps}

Веб-списки и мобильное приложение предлагают меню сохранённых представлений для этих списков
через этот API, поэтому представление, сохранённое в одном клиенте, открывается в другом. Представление
означает то же, что эндпоинт списка: для обращений отсутствие `status` означает все статусы, поэтому оба
клиента сохраняют открытую очередь как три её статуса и открывают представление без статуса как «Все».
Каждый клиент сохраняет только те фильтры, которые его экран умеет показывать и задавать; если
представление содержит фильтр, для которого на экране нет элемента управления, или несколько значений
там, где экран принимает одно, оно всё равно открывается, а меню сообщает, сколько значений было
пропущено.
