# Добавление языка

На этой странице описано, как перевести BottleCRM на новый язык; сквозной пример: персидский
(`fa`). Инфраструктура готова на всех трёх уровнях, поэтому новый язык означает работу по переводу
плюс несколько однострочных регистраций. Ориентируйтесь примерно на 1 900 строк API (из них около
260 названий стран и валют), 4 600 строк веба и 4 000 строк мобильного приложения.

Сначала прочитайте [Локализация](index.md), чтобы понять, как выбирается язык, и
[Добавление строки](adding-strings.md) о форматах каталогов. Если язык пишется справа налево,
прочитайте также [Языки с письмом справа налево](right-to-left.md): вёрстке нужна работа помимо
перевода.

## Перед началом {#before-you-start}

1. **Откройте issue** с указанием, какой язык вы добавляете и будете ли переводить веб-приложение,
   мобильное приложение или оба, чтобы два человека не переводили одно и то же. Если вы берёте
   только веб-приложение, так и напишите: мобильная часть тогда отслеживается отдельно.
2. **Выберите код языка.** Используйте простой код ISO 639-1 (`fa`, `de`, `pt`), один и тот же на
   всех трёх уровнях. Регион добавляйте, только если язык действительно различается по регионам
   (`pt-BR` рядом с `pt`). Именно этот код хранится в `User.language` и с ним сопоставляется
   `Accept-Language`; региональный запрос (`fa-IR`) автоматически откатывается к базовому языку.
3. **Составьте глоссарий.** Скопируйте [Русский глоссарий](glossary-ru.md) в
   `docs/EN/localization/glossary-<code>.md` (добавьте его в nav в `mkdocs.yml`) и заполните
   термины до перевода экранов: лид, сделка, компания, обращение, воронка, этап, слова статусов и
   их грамматический род, если он есть в языке. Глоссарий, согласованный заранее, и обеспечивает,
   что четыре тысячи строк, переведённые за несколько недель, говорят одно и то же.

## 1. API {#1-api}

Зарегистрируйте язык в `backend/crm/settings.py` под его собственным названием, чтобы выпадающий
список показывал его на этом языке, на каком бы языке ни был интерфейс:

```python
LANGUAGES = [("en", "English"), ("ru", "Русский"), ("fa", "فارسی")]
```

Затем создайте и заполните каталоги:

```bash
cd backend
uv run python manage.py update_messages -l fa       # creates <app>/locale/fa/LC_MESSAGES/django.po
# translate every msgstr in each django.po
uv run python manage.py update_messages --compile   # builds the .mo files
```

- **Формы множественного числа.** Задайте в заголовке `Plural-Forms` каждого нового файла `.po`
  правило языка (персидский: `nplurals=2; plural=(n > 1);`, правило GNU gettext для этого языка) и
  дайте каждой записи `msgid_plural` столько же форм `msgstr[n]`.
- **Контексты.** Записи с `msgctxt` (`"ticket status"`, `"deal outcome"`) существуют потому, что
  некоторым языкам нужно разное слово в зависимости от сущности. Переводите каждую для её сущности,
  даже если в вашем языке слова совпадают.
- **Письма.** Шаблоны в `<app>/templates/` переводятся через те же каталоги; проверьте и темы
  писем, это отдельные записи.
- **Страны и валюты** хранятся записями в каталоге `common` (из них формируется
  `GET /api/org/locales/`).
- **Миграция не нужна:** `User.language` и `Org.default_language` проверяются по `LANGUAGES`, а не
  хранятся как choices.

`common/tests/test_translations.py` падает, пока не переведена каждая запись и пока есть хоть одна
fuzzy-запись.

## 2. Веб {#2-web}

Добавьте код в `locales` в `frontend/project.inlang/settings.json`. Затем скопируйте каждый
`frontend/messages/**/en.json` в `fa.json` рядом с ним и переведите значения:

```bash
cd frontend
for f in messages/en.json messages/*/en.json; do cp "$f" "${f%en.json}fa.json"; done
```

- Сохраняйте ключи и `{placeholders}` в точности; переводите только текст.
- **Множественное число.** Сообщению с ветками `"match"` нужна ветка для каждой категории
  множественного числа языка. У `Intl.PluralRules('fa')` есть `one` и `other`; у русского `one`,
  `few`, `many` и `other`; у арабского шесть. `messages.test.js` берёт категории из `Intl` и падает
  на пропущенной. Язык может превратить обычное сообщение в сообщение с множественным числом там,
  где английскому это не нужно.
- **Собственное название языка** записывается в `language_name` в `messages/fa.json` (`"فارسی"`).
  Выпадающий список в профиле показывает каждый язык через этот ключ.
- **Форматирование.** `intlLocale` в `src/lib/i18n/locale.js` сопоставляет локали интерфейса тег
  `Intl`, по которому форматируются даты и числа. Неизвестная локаль используется как есть, и для
  большинства языков это правильно (`fa` даёт персидские цифры и персидский календарь). Добавляйте
  запись, только чтобы закрепить регион, как `ru` с `ru-RU`.
- **Направление.** `textDirection` в том же файле уже знает языки с письмом справа налево и
  выставляет для них `dir="rtl"` на `<html>`.

Запустите `pnpm run check`, `pnpm run lint` и `pnpm test`; откройте переведённые страницы и
проверьте их на 390px (брейкпоинт телефона), где более длинный язык вылезает за границы первым.

## 3. Мобильное приложение {#3-mobile}

Скопируйте каждый фрагмент и удалите из копии записи метаданных `@key` (их хранит только шаблон):

```bash
cd mobile
for f in lib/l10n/parts/*/en.json; do
  python3 -c 'import json,sys; d=json.load(open(sys.argv[1])); json.dump({k:v for k,v in d.items() if not k.startswith("@")}, open(sys.argv[2],"w"), ensure_ascii=False, indent=2)' "$f" "${f%en.json}fa.json"
done
# translate lib/l10n/parts/*/fa.json, including "languageName" in parts/core
dart run tool/l10n_merge.dart && flutter gen-l10n
```

Множественное число использует синтаксис ICU (`{count, plural, =1{...} other{...}}`) и, как и в
вебе, требует категорий языка. `flutter_localizations` уже переводит собственные виджеты Flutter
(выбор даты, меню копирования и вставки) для всех основных языков и задаёт направление текста по
локали. Запустите `flutter analyze` и `flutter test`; экранные тесты `*_ru_test.dart` служат
образцом для `*_fa_test.dart`, который отрисовывает экран на новом языке в ширину телефона.

## 4. Регистрация сразу везде {#4-register-it-everywhere-at-once}

`common/tests/test_language_lists.py` требует, чтобы `settings.LANGUAGES`, `locales` веба и
мобильные фрагменты предлагали в точности одинаковый набор языков. Язык, который предлагает один
клиент и не предлагает другой, означал бы вариант выбора, который другой клиент не может отобразить.

Это определяет, как разбить работу на pull request'ы, поскольку полнота каталогов проверяется
пофайлово:

1. **Один PR на каждый модуль веба** (Лиды, Контакты, Компании, Сделки, Обращения, Настройки и так
   далее), в каждом полностью переведённый `messages/<module>/fa.json` этого модуля. Эти файлы
   проверяются на полноту, как только появляются, но ничто их не показывает, пока язык не
   зарегистрирован.
2. **Один PR для каталогов API**, `<app>/locale/fa/`, пока без добавления в `LANGUAGES`.
3. **Один PR для мобильных фрагментов вместе с регистрацией:** `LANGUAGES`, `locales` в
   `project.inlang` и `lib/l10n/parts/*/fa.json`, чтобы три списка изменились в одном коммите и
   язык появился везде в один день.

Если вы переводите только веб-приложение, остановитесь после шага 1 и напишите об этом в issue:
регистрация языка тогда ждёт каталогов API и мобильного приложения.

## 5. Проверка {#5-review}

- Попросите носителя языка прочитать экраны, а не только файлы каталогов: слово, верное в списке,
  может оказаться неверным на кнопке.
- Сверьте термины глоссария на всех трёх уровнях: одно английское слово не должно переводиться
  двумя способами (`test_translations.py` проверяет это внутри API).
- Посмотрите самые длинные экраны на 390px: таблицы, превращённые в карточки, панель вкладок,
  кнопки с длинными подписями и дашборд «Сегодня». Приложите к первому pull request скриншот
  страницы лидов в этой ширине.
- Никаких длинных тире в переводах: тесты на всех трёх уровнях их отклоняют.

## Чек-лист {#checklist}

- [ ] Открыт issue, страница глоссария добавлена в `docs/EN/localization/`.
- [ ] API: язык в `LANGUAGES`, каждый `django.po` переведён, `.mo` скомпилированы и закоммичены.
- [ ] Веб: код в `project.inlang/settings.json`, каждый `messages/**/<code>.json` переведён, `language_name` задан.
- [ ] Мобильное приложение: каждый `lib/l10n/parts/*/<code>.json` переведён, ARB объединены и закоммичены.
- [ ] Справа налево: вёрстка проверена, как описано в [Языки с письмом справа налево](right-to-left.md).
- [ ] `pnpm run check`, `pnpm run lint`, `pnpm test`, `uv run pytest`, `flutter test` проходят.
- [ ] Скриншоты на 390px приложены к pull request.
