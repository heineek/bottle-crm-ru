# Локализация

Интерфейс поставляется на английском (исходном языке) и русском. API, веб-приложение и мобильное
приложение берут строки из каталогов сообщений и одинаково выбирают язык. Этот раздел для
разработчиков, которые хотят добавить строку, исправить перевод или подключить новый язык.

| Страница | Когда читать |
|---|---|
| [Добавление строки](adding-strings.md) | Вы добавляете или меняете любой текст, который видит пользователь, на любом из трёх уровней |
| [Добавление языка](adding-a-language.md) | Вы хотите перевести BottleCRM на язык, которого ещё нет в поставке |
| [Языки с письмом справа налево](right-to-left.md) | Новый язык пишется справа налево (персидский, арабский, иврит, урду) |
| [Русский глоссарий](glossary-ru.md) | Вы переводите на русский или проверяете русскую строку |

## Что переводится {#what-is-translated}

| Уровень | Каталоги | Инструменты |
|---|---|---|
| API | `backend/<app>/locale/<lang>/LC_MESSAGES/django.po` (и скомпилированный `.mo`), по одному на каждое приложение Django | Django `gettext`, `manage.py update_messages` |
| Веб | `frontend/messages/<module>/<lang>.json`, плюс `frontend/messages/<lang>.json` для общих строк | [Paraglide JS](https://inlang.com/m/gerre34r/library-inlang-paraglideJs) (`project.inlang/settings.json`) |
| Мобильное приложение | `mobile/lib/l10n/parts/<module>/<lang>.json`, объединяются в `lib/l10n/app_<lang>.arb` | Flutter `gen-l10n` (`mobile/l10n.yaml`) |

Через эти каталоги проходят сообщения об ошибках API, сообщения валидации, письма, PDF, подписи
вариантов выбора (статусы, приоритеты) и каждый экран обоих клиентов. Даты, числа и денежные суммы
форматируются по локали (`Intl` в вебе, `intl` в мобильном приложении), а не вручную.

Каталоги разделены по модулям, чтобы два человека, переводящие разные модули, никогда не правили
один файл и чтобы модуль можно было проверить и выпустить отдельно.

## Какой язык используется {#which-language-is-used}

Порядок один на всех уровнях и записан трижды, чтобы каждый уровень применял его без лишнего
запроса:

1. Собственный выбор пользователя, `User.language`. Задаётся на странице профиля (веб) или на
   экране «Язык» в разделе «Профиль» (мобильное приложение) через `PATCH /api/profile/` с
   `{"language": "en"}`; пустая строка сбрасывает выбор. Он общий для всех организаций, в которых
   состоит пользователь.
2. Языки клиента: браузера или телефона, передаются в `Accept-Language`.
3. Язык организации по умолчанию, `Org.default_language`, который администратор задаёт на странице
   настроек организации.
4. Английский.

| Уровень | Где задан порядок |
|---|---|
| API | `backend/common/locale.py` (`resolve_language`), активируется для каждого запроса в `GetProfileAndOrg` |
| Веб | `frontend/src/lib/i18n/locale.ts` (`resolveLocale`), применяется в `src/hooks.server.ts` |
| Мобильное приложение | `mobile/lib/services/app_language.dart` (`resolveLanguage`), применяется в `languageProvider` |

Клиенты берут выбор пользователя и язык организации по умолчанию из claims `language` и
`org_settings.default_language` access-токена, поэтому выбор языка обновляет токен. Оба клиента
передают `Accept-Language` в каждом запросе к API, так что ошибка, сформированная API, приходит на
том же языке, что и страница вокруг неё. Веб выставляет `lang` и `dir` на `<html>` по выбранной
локали; Flutter сам задаёт направление текста по локали приложения.

Письма следуют за читателем: участник организации получает письмо на своём языке (а если он не
выбран, на языке организации по умолчанию), а клиент (счета, коммерческие предложения, опросы
CSAT, портал) всегда получает язык организации по умолчанию, поскольку у контакта нет `User`, в
котором хранился бы выбор. PDF всегда формируются на языке организации по умолчанию. Задачи Celery
выбирают язык через `common.locale.language_for_user` или `language_for_org`.

Страны, валюты и список языков для выпадающих списков приходят из `GET /api/org/locales/` уже
названными на языке запроса, поэтому ни один клиент не хранит собственный переведённый список
стран.

## Что никогда не переводится {#what-is-never-translated}

Всё, что ввёл тенант (названия записей, названия этапов, подписи дополнительных полей, теги,
переопределения `Org.terminology` из отраслевого пакета), сохранённый текст вроде строк журнала
аудита и ленты активности, payload вебхуков, значения `code` ошибок и строки логов. Перевод
никогда не должен менять то, что API сохраняет или отправляет в другую систему: клиенты передают
коды, а не переведённые подписи.

## Проверки {#the-checks}

Они запускаются в CI и падают на недоделанном переводе, поэтому пропущенная строка обнаруживается
на ревью, а не английским словом на переведённом экране.

| Проверка | Что она ловит |
|---|---|
| `backend/common/tests/test_language_lists.py` | Три уровня предлагают разные языки |
| `backend/common/tests/test_translations.py` | Непереведённую или fuzzy-запись `.po`, устаревший `.mo`, длинное тире, одну английскую строку, переведённую двумя способами |
| CI «Check message catalogs are up to date» | Обёрнутую строку без записи в каталоге |
| `frontend/src/lib/i18n/messages.test.ts` | Отсутствующие ключи, изменённые плейсхолдеры, множественное число без нужных языку форм, ключ, определённый в двух модулях |
| `frontend/src/lib/i18n/strategy.test.ts` | Плагин Vite и `pnpm i18n`, скомпилированные с разными стратегиями локали |
| `mobile/test/unit/app_language_test.dart` | Отсутствующие ключи или плейсхолдеры, пустое сообщение, порядок выбора языка |
| `mobile/test/unit/l10n_merge_test.dart` | Файлы ARB, устаревшие относительно фрагментов, ключ, определённый в двух модулях |
